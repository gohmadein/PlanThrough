# PlanThrough

> 一张图，无限穿透。

PlanThrough 是一个把甘特图、思维导图式层级展开、进度归并和顺序执行结合在同一画布中的项目计划工具。横轴表示真实时间，纵轴表示可自定义的事件分类；一级节点用于展示项目骨架，二级和三级节点可以直接在主视图中展开与收起。

## 主要功能

### 时间与层级

- 一级、二级、三级任务都按照开始时间和完成时间严格定位。
- 一级节点按全局分类排列；展开后，子节点在父节点的半透明框内重新按分类排列。
- 父节点展开时，框内局部时间轴会自动细化一级，例如“年 → 月”“月 → 日”。
- 底部时间轴会根据项目跨度和缩放比例自动切换年、季度、月、周、日颗粒度。
- 支持同时展开多个节点，并在一张画布中自由缩放和滚动查看。

### 并发与关系

- 同一父节点下的时间重叠显示为同级并发。
- 无父子关系的时间重叠显示为跨模块并行。
- 橙色、紫色并发边界贯穿任务区域，鼠标悬停时显示解释和时间范围。
- 当前时间线支持鼠标悬停说明。
- 兄弟节点之间使用不同粗细的实线连接，线条粗细随任务层级变化。

### 顺序执行

- 点击第一个一级节点左上方的起点，正式启动项目。
- 启动时所有节点进度统一初始化为 `0%`。
- 系统按照一级节点时间顺序，并递归按照子节点时间顺序逐个解锁任务。
- 灰色圆点表示未解锁，黄色圆点表示当前任务，绿色圆点表示已完成。
- 当前任务及其父级使用固定黄色虚线框提示。
- 当前未完成节点通往下一兄弟节点时持续显示黄色断线。
- 当前节点完成时，连接线上播放一次绿色电流动画，随后恢复为普通实线。
- 解锁下一任务后，系统自动展开、滚动定位并打开该任务的编辑面板。
- 全部叶子任务完成后解锁终点；点击终点会播放烟花和项目完成提示。
- 项目完成后仍可继续修改任意节点的状态与进度，方便调试。

### 编辑与计算

- 右侧编辑面板可以修改任务名称、分类、起止时间、状态、进度、权重和人工风险。
- 子节点时间必须完全位于父节点时间范围内。
- 父节点进度由直接子节点按照权重自动归并。
- 深层任务的风险和延误会递归传递到父节点。
- 已完成任务不会继续触发自动延误。
- 支持“完成后开始”和“可并行”两类前置关系，并允许多个前置节点。

### 拖动修改模式

- 从顶部工具栏进入“拖动修改”模式。
- 横向拖动节点主体可整体平移起止时间，纵向拖动可修改事件分类。
- 拖动节点左右边缘可分别修改开始时间和完成时间。
- 平移父节点时，其完整子任务树会同步平移。
- 拖动过程中的节点、展开框、兄弟连线、并发边界和局部时间轴会实时更新。
- 修改先保存在草稿中，可以选择“保存修改”或退出并放弃。

### 项目、文件与交换

- 项目库页面支持查看、搜索、打开和删除当前浏览器中的多个项目。
- 新建项目不会覆盖旧项目。
- 每个节点都可以上传、查看、下载和删除附件。
- 项目可以导出为 JSON，再由其他用户导入后继续编辑。

## 环境要求

开始前请安装：

- [Git](https://git-scm.com/)
- [Node.js](https://nodejs.org/) `22.13.0` 或更高版本
- npm（安装 Node.js 时会一并安装）

检查版本：

```bash
git --version
node --version
npm --version
```

## 克隆并启动

### 1. 克隆项目

```bash
git clone https://github.com/gohmadein/PlanThrough.git
cd PlanThrough
```

### 2. 安装依赖

```bash
npm install
```

### 3. 启动开发模式

```bash
npm run dev
```

终端会显示本地访问地址，通常为：

```text
http://localhost:3000
```

在浏览器中打开该地址即可使用。开发模式支持代码修改后的自动刷新。

### 4. 停止服务

回到运行服务的终端，按：

```text
Ctrl + C
```

## 生产模式运行

首次运行：

```bash
npm install
npm run build
npm run start
```

已经安装依赖并构建过时，可以直接执行：

```bash
npm run start
```

修改代码后，需要重新执行 `npm run build`。

## 验证项目

运行构建和自动测试：

```bash
npm test
```

只执行生产构建：

```bash
npm run build
```

## 数据保存说明

- 项目数据保存在当前浏览器的 `localStorage` 中。
- 附件内容保存在当前浏览器的 `IndexedDB` 中。
- 更换浏览器、设备或清除浏览器数据后，本地项目可能无法继续访问。
- 建议定期使用顶部“导出”按钮备份项目 JSON。
- 导出的 JSON 包含项目结构和附件元数据，但不包含附件文件本身；附件需要另外保存和传输。
- GitHub 仓库只包含程序源代码，不包含你在浏览器中创建的项目和上传的附件。

## 常见问题

### `npm install` 失败

确认 Node.js 版本至少为 `22.13.0`，然后重新执行：

```bash
node --version
npm install
```

### 端口 3000 被占用

开发服务器可能会自动选择其他端口，请以终端打印的地址为准；也可以先停止占用该端口的旧服务。

### 页面中没有原作者创建的项目

这是正常现象。项目数据保存在每个用户自己的浏览器里，不会随 Git 仓库下载。需要让项目提供者另外导出 JSON，再在页面顶部点击“导入”。

### 附件导入后无法下载

JSON 只保存附件名称、大小等元数据，不包含文件内容。请向项目提供者单独索取原始附件。
